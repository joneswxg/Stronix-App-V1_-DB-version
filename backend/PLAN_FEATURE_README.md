## 数据库设计

### 涉及的表
1. **training_plans** - 训练计划主表
2. **plan_actions** - 计划动作关联表
3. **plan_sets** - 计划组数据表
4. **action** - 动作信息表（已存在）
5. **user** - 用户表（已存在）

### 关键字段说明
- `is_template`: 标记是否为模板计划
- `record_bilateral`: 标记是否记录左右重量
- `weight`: 动作总容量（自动计算）
- `left_weight/right_weight`: 双侧训练的左右重量

## API接口

### 基础URL
```
http://localhost:6000/api/plans
```

### 主要接口
1. `GET /templates` - 获取模板计划列表
2. `GET /personal` - 获取个人计划列表
3. `GET /{plan_id}` - 获取计划详情
4. `POST /create` - 创建新计划
5. `POST /copy/{template_id}` - 复制模板计划
6. `PUT /{plan_id}` - 更新计划
7. `DELETE /{plan_id}` - 删除计划
8. `GET /{plan_id}/can_delete` - 检查是否可删除

详细的API文档请参考 `API_PLAN_DOCS.md`

## 容量计算逻辑

### 普通训练
```
容量 = Σ(重量 × 次数)
```

### 双侧训练
```
容量 = Σ((左重量 + 右重量) × 次数)
```

### 示例
```json
// 普通训练
{
    "record_bilateral": false,
    "sets": [
        {"weight": 20.0, "reps": 12},  // 容量: 20 × 12 = 240
        {"weight": 22.5, "reps": 10}   // 容量: 22.5 × 10 = 225
    ]
    // 总容量: 240 + 225 = 465
}

// 双侧训练
{
    "record_bilateral": true,
    "sets": [
        {"left_weight": 10.0, "right_weight": 10.0, "reps": 12},  // 容量: (10+10) × 12 = 240
        {"left_weight": 12.5, "right_weight": 12.5, "reps": 10}   // 容量: (12.5+12.5) × 10 = 250
    ]
    // 总容量: 240 + 250 = 490
}
```

## 权限控制

### 模板计划
- 所有用户可查看
- 不可修改或删除
- 可复制到个人计划

### 个人计划
- 只有创建者可查看、修改、删除
- 需要登录验证
- 正在进行训练时不可删除

## 错误处理

### 错误码体系
- 200: 成功
- 400: 请求参数错误
- 401: 未登录
- 403: 无权限操作
- 404: 资源不存在
- 409: 业务逻辑冲突
- 500: 服务器错误

### 多语言支持
通过请求头 `Accept-Language` 控制：
- `zh_CN`: 中文（默认）
- `en_US`: 英文

## 事务处理

### 创建计划事务
1. 插入 `training_plans` 表
2. 插入 `plan_actions` 表
3. 插入 `plan_sets` 表
4. 如果任何步骤失败，回滚所有操作

### 更新计划事务
1. 更新 `training_plans` 表
2. 删除旧的 `plan_actions` 和 `plan_sets` 记录
3. 插入新的 `plan_actions` 和 `plan_sets` 记录
4. 如果任何步骤失败，回滚所有操作
